# 배포 안내

현재 공개 주소는 [fe-application-timeline.vercel.app](https://fe-application-timeline.vercel.app/)입니다. Vercel CLI로 같은 프로젝트에 프로덕션 배포하고 있습니다.

GitHub와 Vercel의 자동 배포 연결은 아직 완료하지 않았습니다. GitHub에 push하는 것만으로 공개 사이트가 바뀌지는 않습니다.

## 배포 설정

- 프레임워크: Vite
- 빌드 명령: `npm run build`
- 출력 폴더: `dist`
- 기본 경로: `/`

`vercel.json`은 `/experiences/<slug>` 직접 접근과 새로고침을 처리합니다. 기존 프로젝트 연결을 유지하며 새로운 Vercel 프로젝트를 만들지 않습니다.

## 수정부터 공개까지

1. 변경한 콘텐츠와 코드의 범위를 확인하고 관련 검사를 실행합니다.
2. `npm run check`, 실제 공개 빌드와 필요한 회귀 검사를 통과시킵니다.
3. 검토한 소스만 공개 저장소에 반영합니다. 다른 작업의 변경 사항을 함께 커밋하지 않습니다.
4. 인증된 기존 프로젝트에서 `vercel deploy --prod`로 배포합니다.
5. 배포가 `READY`가 된 뒤 고정 공개 주소를 확인합니다.

홈과 변경한 상세 URL을 로그인 없이 열 수 있어야 합니다. 공개 서버의 콘텐츠 manifest와 변경된 파일이 검증한 빌드와 일치하는지도 확인합니다. 면접관에게는 개별 배포 URL이 아닌 고정 공개 주소를 전달합니다.

배포가 실패했다면 공개 완료로 보고하지 않습니다. 실패 원인을 해결한 뒤 같은 프로젝트에 다시 배포하며, 기존 정상 배포를 임의로 삭제하지 않습니다.

## 공개 파일과 비밀정보

`.env.local`, `.vercel`, `.openai`, `.content-sync`, 의존성·빌드·임시 결과는 공개 소스에 포함하지 않습니다. `.env.example`에는 실제 자격증명이 아닌 변수 이름과 예시만 둡니다.

초안 필터는 웹사이트 번들에 대한 규칙입니다. 공개 GitHub에 커밋한 Markdown과 `public/`에 넣은 이미지는 게시 상태와 무관하게 공개됩니다. 개인정보와 비공개 자료를 먼저 검토하세요.

## 이후 Git 자동 배포를 연결한다면

계정의 GitHub 연결을 완료하고 기존 Vercel 프로젝트의 Production Branch를 `main`으로 지정한 뒤, 실제 커밋으로 자동 배포를 확인합니다. 연결 성공을 확인하기 전에는 현재 CLI 배포 절차를 유지합니다.

GitHub Pages 워크플로는 수동 실행용 선택지입니다. 현재 공개 주소를 갱신하는 절차가 아니므로 Vercel 배포와 함께 실행하지 않습니다.
