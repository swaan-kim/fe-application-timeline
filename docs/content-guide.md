# 콘텐츠 편집

## 경험 추가와 수정

경험 하나는 `content/experiences/<slug>.md` 파일 하나입니다. 파일을 추가·삭제하면 타임라인, 목록, 상세 경로에 반영됩니다. 게시한 파일명은 공유 URL이므로 이후 바꾸지 않습니다.

```md
---
title: '경험 제목'
category: build
technologies: [react, typescript, vitejs]
startDate: '2026-04-01'
endDate: '2026-06-01'
status: draft
---

## 목적

누구의 어떤 문제를 해결하려 했는지 씁니다.

## 의도

어떤 선택을 했고 왜 그렇게 했는지 씁니다.

## 성과

확인한 결과, 만든 산출물 또는 배운 점을 씁니다.
```

본문에는 `## 목적`, `## 의도`, `## 성과`를 이 순서로 한 번씩 둡니다. 다른 제목, 표, 코드 블록, HTML은 지원하지 않습니다. 문단·목록·굵게·기울임·링크와 독립된 자료 이미지를 사용할 수 있습니다. 링크는 `http`, `https`, `mailto`를 허용합니다.

### 주요 필드

- `category`: `build`, `work`, `grow`
- `status`: `draft`, `published`, `archived`
- `startDate`, `endDate`: 실제 `YYYY-MM-DD` 날짜. 종료일을 생략하면 단일 사건입니다.
- `ongoing`: 진행 중이면 `true`. 타임라인 기준일에 맞춘 `endDate`도 함께 지정합니다.
- `technologies`: 선택 항목. 지원하는 기술 ID를 중복 없이 최대 4개 지정합니다. 생략하거나 `[]`로 두면 표시하지 않습니다. 지원 ID는 `src/domain/technology.ts`에서 확인합니다.

화면에는 날짜를 월 단위로 표시합니다. 일자는 타임라인 배치에 사용하므로, 사용자가 확인한 기간 안에서 초·후반 정도의 근사치를 쓸 수 있습니다. 기준일을 바꾸면 진행 중인 활동의 `endDate`도 갱신합니다. 활동이 끝나면 `ongoing`을 제거하거나 `false`로 바꾸고 종료일을 수정합니다.

## 공개 범위

개발 화면에는 보관 항목을 제외한 초안도 표시합니다. 공개 빌드에는 `published`와 설정의 `publicDraftIds`에 명시된 초안만 포함합니다. 새 초안은 자동 공개되지 않으며, `archived`는 승인 목록에 있어도 제외합니다.

현재 여섯 경험은 작성 상태 그대로 공개하도록 승인되어 있습니다. 상태를 임의로 바꾸기보다, 최종 원고를 검토한 뒤 `published`로 전환합니다. 게시 항목에는 빈 본문·목업 문구·제목 검사가 적용됩니다. Build / Work / Grow마다 공개 항목이 필요하며, 9개를 넘으면 탐색성 경고를 제공합니다.

웹사이트에서 숨긴다고 GitHub에서도 비공개가 되는 것은 아닙니다. 공개 저장소에 커밋한 Markdown과 `public/` 자료는 누구나 읽을 수 있습니다. 전화번호·생년월일·학번 등 불필요한 개인정보와 비공개 자료를 넣지 않습니다.

## 기준일과 타임라인 전용 활동

`src/content/application.config.ts`에서 이름·지원 분야·기준일·차트 표시 시작일을 관리합니다. 콘텐츠 검증 범위는 기준일 이전 12개월이며, 차트는 `chartStartDate`부터 더 짧게 표시할 수 있습니다. 막대만 표시 범위에 맞춰 자르고 실제 기록 날짜는 유지합니다.

하단 상세 없이 차트에만 표시할 활동은 `chartAnnotations`에 추가합니다. `id`, `category`, `title`, `startDate`, 선택적 `endDate`, `chartOnly: true`를 지정합니다. 모바일에서는 차트와 함께 숨겨지며, 상세 경로나 다음 경험 순서에 포함되지 않습니다.

과거 기록은 `archived`로 바꾸면 현재 12개월 범위 밖에서도 보관할 수 있습니다. 날짜 형식과 기간 역전 검사는 모든 파일에 적용됩니다.

`githubUrl` 필드는 유지하지만 빈 문자열을 허용합니다. 값이 있다면 `https://github.com/<username>` 형식의 프로필 주소를 사용합니다. 공개 검사에 필수는 아니며 홈에는 링크를 표시하지 않습니다. 프로젝트별 근거 링크는 각 경험 본문에서 관리합니다.

## 이미지와 GIF

자료는 `public/media/experiences/<id>/`에 넣습니다. 파일명은 소문자 영문·숫자·하이픈, 확장자는 png·jpg·jpeg·webp·gif를 사용합니다.

```md
![화면에 대한 짧은 설명](/media/experiences/project-b/home.png)
```

이미지는 다른 글과 섞지 않고 독립된 문단으로 작성합니다. 설명은 대체 텍스트와 캡션으로 사용합니다. 이미지를 누르면 원본이 열리며, 별도 ‘원본 보기’ 문구는 표시하지 않습니다. GIF는 사용자가 재생해야 나타납니다.

원본 치수는 `src/content/experience-media.ts`의 경로별 `width`, `height`에 등록합니다. 원본을 교체하면 이 값도 갱신하세요. 미등록 이미지도 기존 방식으로 표시하지만, 치수를 등록하면 이미지가 로딩되기 전에 필요한 공간을 확보할 수 있습니다. 브라우저 테스트는 등록 치수와 실제 파일의 치수가 같은지도 확인합니다.

나란히 볼 화면은 연속된 이미지 문단에 `gallery` 제목을 붙입니다. 이미지 사이에 빈 줄을 둡니다.

```md
![꾸미기 시작](/media/experiences/project-b/customize-start.png 'gallery')

![스크롤 후 미리보기](/media/experiences/project-b/customize-scrolled.png 'gallery')
```

두 장 이상일 때 묶이며 데스크톱 2열, 480px 이하 1열입니다. 강아지 스마트폰 캡처만 메타데이터에 `layout: 'phone'`을 지정하며 이미지 높이를 최대 36rem으로 제한합니다. 원본 비율은 유지하고 자르지 않습니다. 문서·슬라이드·아키텍처에는 이 설정을 적용하지 않습니다.

## Notion 가져오기와 검사

Markdown이 최종 원본이며 Notion은 단방향 입력 수단입니다.

```bash
npm run content:notion:pull
npm run content:notion:pull -- --apply --run <미리보기 ID>
```

첫 명령은 `.content-sync/`에 후보와 변경 요약만 만들고 Markdown을 수정하지 않습니다. 검토 후 두 번째 명령으로 반영합니다. 양쪽이 바뀌었거나 미리보기 이후 파일이 수정되면 덮어쓰지 않고 중단합니다. 이미지 가져오기는 지원하지 않습니다. 이미지와 기술 목록은 로컬에서 관리하며 기술 목록은 가져오기 후에도 보존됩니다.

연결 설정, 지원 서식과 충돌 해결법은 [Notion 설정](notion-template.md)을 참고하세요. 비밀키는 `.env.local`에만 두고 저장소에 커밋하거나 `VITE_` 접두사를 붙이지 않습니다.

```bash
npm run content:check
npm run content:publish-check
```

오류에는 파일과 필드가 표시됩니다. 날짜·상태·본문·자료 경로를 수정한 뒤 다시 검사합니다. 게시 제목은 문제나 기여가 드러나는 8–24자를 권장하며, 36자를 넘거나 의미가 불분명한 제목은 차단합니다. 측정하지 않은 수치나 실행하지 않은 테스트 결과를 추가하지 않습니다.
