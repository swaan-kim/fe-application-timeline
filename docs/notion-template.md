# Notion 콘텐츠 템플릿

Notion에서 경험을 작성한 뒤 검토된 Markdown으로 가져오기 위한 설정입니다. 사이트가 Notion을 실시간으로 읽지는 않으며 토큰은 브라우저에 전달되지 않습니다.

## 1. 데이터베이스 속성

속성 이름과 유형을 아래처럼 정확히 만듭니다.

| 속성     | 유형   | 값                         |
| -------- | ------ | -------------------------- |
| 제목     | 제목   | 상세 페이지 제목           |
| Slug     | 텍스트 | 소문자 영문·숫자·하이픈    |
| Category | 선택   | Build, Work, Grow          |
| 기간     | 날짜   | 시작일과 선택적 종료일     |
| 상태     | 선택   | Draft, Published, Archived |

`Slug`는 Markdown 파일명과 공개 URL이 됩니다. 한 번 게시한 뒤에는 바꾸지 않습니다. 삭제하려는 항목은 Notion 페이지를 지우는 대신 `Archived`로 변경합니다.

## 2. 페이지 본문

각 데이터베이스 페이지 본문에는 아래 H2 세 개를 순서대로 한 번씩 둡니다.

```md
## 목적

## 의도

## 성과
```

각 영역에는 일반 문단, 글머리표, 번호 목록, 굵게, 기울임, `http`·`https`·`mailto` 링크만 사용합니다. 이미지, 표, 임베드, 코드 블록과 중첩 블록은 변환 중 조용히 누락시키지 않고 오류로 알려줍니다. 일반 텍스트의 백틱·대괄호·`#`·`&copy;`는 원문 그대로 보존하며, 문단 내부 줄바꿈도 변환합니다. 텍스트나 링크를 손실 없이 왕복할 수 없는 서식은 미리보기 생성 전에 거절합니다.

## 3. 읽기 전용 연결

1. Notion Developer Portal에서 내부 연결을 만들고 콘텐츠 읽기 권한만 부여합니다.
2. 데이터베이스 메뉴의 `연결 추가`에서 해당 연결을 공유합니다.
3. `.env.example`을 참고해 프로젝트 루트에 `.env.local`을 만듭니다.

```dotenv
NOTION_TOKEN=secret_...
NOTION_DATA_SOURCE_ID=...
```

`.env.local`은 Git에서 제외됩니다. `VITE_` 접두사를 붙이면 브라우저에 노출될 수 있으므로 사용하지 않습니다.

## 4. 미리보기와 반영

```bash
npm run content:notion:pull
```

결과에는 추가, 변경, 동일, 로컬만 변경, 충돌 개수와 미리보기 ID가 표시됩니다. 실제 Markdown은 바뀌지 않습니다.

```bash
npm run content:notion:pull -- --apply --run <미리보기 ID>
```

반영할 때 미리보기 후보와 로컬 Markdown의 해시를 다시 확인합니다. 둘 중 하나라도 미리보기 이후 바뀌었거나 양쪽이 동시에 수정됐다면 전체 반영을 중단합니다. 충돌은 Markdown과 Notion 중 유지할 내용을 직접 합친 뒤 새 미리보기를 만들어 해결합니다.

반영 명령은 동시 실행을 잠금으로 막고, 검증한 후보 내용을 그대로 사용합니다. 기록 직전에도 로컬 파일을 확인합니다. 실패하면 이번 실행이 기록한 내용만 복구하고, 그 뒤 사용자가 수정한 파일은 보존한 채 복구 자료 위치를 안내합니다. 외부 편집기는 이 잠금을 따르지 않으므로 반영 중에는 같은 파일 편집을 잠시 멈추는 편이 안전합니다.

`archived`로 바꾼 과거 경험은 현재 12개월 밖이어도 보관할 수 있습니다. 날짜 자체가 잘못됐거나 종료일이 시작일보다 앞선 경우는 여전히 오류입니다. `apply.lock`이 남았다면 실행 중인 가져오기 작업이 없는지 확인하고, 실패 메시지의 백업·후보를 검토한 뒤 잠금을 정리하세요. 자동으로 다른 실행의 잠금을 삭제하지 않습니다.
