## 목적

AI가 처음 의도에서 벗어나지 않도록 안내하고, 수정한 결과도 같은 기준으로 검토하는 방법을 고민했습니다. 네이버 블로그 자동화를 사례로, 초기 요청·컨벤션·QA·회귀 테스트를 하나의 작업 흐름으로 연결했습니다.

## 의도

- **초기 방향 · 엇나가기 전에 기준 맞추기:** 독자의 문제와 핵심 메시지, 사람이 검토할 지점을 요청서에 먼저 정했습니다. ‘비개발자도 이해할 수 있게’라는 목적은 ‘낯선 용어를 풀고 예시를 넣기’로 구체화해, 작성과 수정이 같은 방향을 향하도록 했습니다.
- **컨벤션 · 단계가 바뀌어도 같은 규칙 쓰기:** 제목·본문·메타데이터의 형식과 문단 간격을 공통 규칙으로 정했습니다. 원고 작성과 편집기 입력이 서로 다른 형식을 기대하지 않도록, 반복할 규칙을 템플릿과 지침으로 분리했습니다.
- **QA · 통과 기준을 실제 화면까지 연결하기:** 글자 수·제목 중복은 Python으로 검사하고, 문단 순서·들여쓰기·누락은 편집기 화면에서 확인하도록 나눴습니다. 원고 파일이 맞다는 이유만으로 화면도 맞다고 판단하지 않기 위해서입니다.
- **회귀 테스트 · 수정 뒤에도 지켜야 할 기준 남기기:** 원고 검사에는 정상 원고의 통과, 중복 제목과 소제목 간격 오류의 실패를 테스트로 남겼습니다. 화면 제어 규칙을 바꿀 때도 입력 대상·문단 순서·서식을 다시 확인해야 한다고 봤습니다. 바꾼 부분뿐 아니라 영향을 받는 기존 동작까지 점검하기 위한 기준입니다.

## 성과

- **구조화한 작업 흐름:** 요청서·원고 템플릿·검사 스크립트·테스트·화면 검수표를 스킬로 정리했습니다. 편집기 제어는 DOM 탐색 규칙과 중단 조건을 담은 지침으로 구성했습니다.
- **FE 관점의 학습:** 좋은 프롬프트는 시작이고, 컨벤션과 QA는 그 의도를 끝까지 유지하는 장치라고 배웠습니다. 처음 정한 기준을 수정 후 재검증에 다시 쓰고, 마지막에는 실제 화면까지 점검하는 흐름으로 보게 됐습니다.
- **실전 적용 · 교내 2026 UNITHON 최우수상:** 핵심 기획을 맡아 기능 범위와 화면 흐름을 먼저 정리하고, 공통 컨벤션과 완료 기준을 작업 지침으로 남겼습니다. 이를 기준으로 AI의 결과물을 점검하며, 전담한 UI·프론트엔드 목업과 PPT 제작을 병렬로 진행했습니다. 사업계획서는 팀원과 협의해 작성하며, 각 작업이 같은 기획 의도를 따르도록 조율했습니다.

**사례 · 네이버 블로그 편집기 제어 설계**

**최초 DOM 탐색·매핑 → 저장한 규칙으로 묶음 입력 → 필요한 항목만 QA**

DOM 전체를 저장하는 대신, 제목·본문·서식 도구를 역할과 라벨로 찾는 규칙을 재사용하도록 설계했습니다. 로컬 UI 프로필을 지원하는 환경에서는 페이지 주소·프레임·화면 크기도 함께 기록합니다. 예상한 편집기 상태와 다르면 입력을 멈추고, 입력 후에는 제목·문단 순서·누락 여부를 확인하도록 했습니다.
