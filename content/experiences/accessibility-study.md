## 목적

AI가 요청 의도를 유지하고, 수정한 결과도 같은 기준으로 검토하도록 만드는 방법을 공부했습니다. 네이버 블로그 자동화를 사례로, 초기 요청·컨벤션·QA·회귀 테스트의 기준을 정리했습니다.

## 의도

- **목적을 완료 조건으로:** ‘잘 써줘’ 대신 독자·핵심 메시지·검토 항목을 먼저 정했습니다. ‘비개발자도 이해하도록’을 ‘용어 설명과 예시 포함’으로 구체화해, 생성과 검토에 같은 기준을 적용했습니다.
- **작성과 입력 사이의 형식 맞추기:** 제목·본문·메타데이터 구조와 문단 규칙을 템플릿으로 정리했습니다. AI가 만든 원고를 편집기에 옮길 때 구조를 다시 해석하지 않도록, 두 단계가 따를 공통 규칙을 마련했습니다.
- **입력 완료와 화면 완성을 구분:** DOM 요소에 글이 입력돼도 화면이 의도대로 보인다는 보장은 없었습니다. 입력 여부뿐 아니라 실제 렌더링된 결과까지 확인하도록 설계했습니다.
- **수정 후 기존 동작도 재검증:** 검사 로직을 바꿔도 정상·오류 판단이 유지되도록 회귀 테스트를 작성했습니다. 편집기 제어를 수정할 때 다시 확인할 화면 동작도 지침으로 남겼습니다.

## 성과

**실전 적용 1 · 네이버 블로그 자동화**

- **재사용할 수 있는 스킬:** 요청서·원고 템플릿·Python 검사·테스트·화면 검수표를 묶었습니다. 편집기 제어는 DOM 탐색 규칙과 중단 조건을 담은 지침으로 정리했습니다.
- **FE 관점의 학습:** 요청이 구체적이어도 실제 화면까지 의도대로 나오는지는 별도 확인이 필요했습니다. 초기 컨벤션을 QA와 수정 후 재검증의 기준으로 이어 쓰는 것이 중요하다고 배웠습니다.

**편집기 제어 설계**

**최초 DOM 탐색·매핑 → 저장한 규칙으로 묶음 입력 → 입력 결과 QA**

DOM 전체를 복사하는 대신, 제목·본문·서식 도구를 역할·라벨로 찾는 규칙을 재사용하도록 설계했습니다. UI 프로필을 지원하는 환경에서는 URL·프레임·뷰포트도 기록해 같은 편집기 조건에서 규칙을 쓰도록 했습니다. 예상과 다른 화면에서는 입력을 멈추고, 입력 후에는 제목·문단 순서·누락을 확인하도록 지침을 남겼습니다.
