## 목적

AI가 요청 의도를 유지하고, 수정한 결과도 같은 기준으로 검토하도록 만드는 방법을 공부했습니다. 네이버 블로그 자동화를 사례로, 초기 요청·컨벤션·QA·회귀 테스트의 기준을 정리했습니다.

## 의도

- **초기 방향 · 목적을 구체적인 기준으로:** 독자·핵심 메시지·검토할 지점을 먼저 정했습니다. ‘비개발자도 이해하도록’이라는 목적을 ‘낯선 용어를 풀고 예시 넣기’로 바꿔, 작성과 수정의 기준으로 삼았습니다.
- **컨벤션 · 작성부터 입력까지 같은 규칙으로:** 제목·본문·메타데이터 형식과 문단 간격을 템플릿과 지침으로 정리했습니다. 원고를 작성할 때와 편집기에 넣을 때 서로 다른 형식을 쓰지 않기 위해서입니다.
- **QA · 원고뿐 아니라 화면까지:** 글자 수·제목 중복은 Python으로 검사하고, 문단 순서·들여쓰기·누락은 편집기 화면에서 확인하도록 나눴습니다. 원고가 맞아도 입력된 화면은 다를 수 있기 때문입니다.
- **회귀 테스트 · 수정 후에도 기준 지키기:** 정상 원고는 통과하고 중복 제목·소제목 간격 오류는 걸러지도록 Python 검사에 테스트를 남겼습니다. 화면 제어 지침에도 입력 대상·문단 순서·서식을 다시 확인하도록 적어, 기존 동작에 미치는 영향까지 점검하게 했습니다.

## 성과

- **재사용할 수 있는 스킬:** 요청서·원고 템플릿·Python 검사·테스트·화면 검수표를 묶었습니다. 편집기 제어는 DOM 탐색 규칙과 중단 조건을 담은 지침으로 정리했습니다.
- **FE 관점의 학습:** 요청이 구체적이어도 실제 화면까지 의도대로 나오는지는 별도 확인이 필요했습니다. 초기 컨벤션을 QA와 수정 후 재검증의 기준으로 이어 쓰는 것이 중요하다고 배웠습니다.

**실전 적용 · 교내 2026 UNITHON 최우수상**

- 각 작업의 목적·의도에 맞춰 컨벤션을 정하고, AI 결과가 기준에서 벗어날 때만 조정했습니다.
- 핵심 기획, FE UI·목업 구현, PPT 제작을 전담하며 병렬로 진행했습니다. 사업계획서는 팀원과 협의해 작성했습니다.

**사례 · 네이버 블로그 편집기 제어 설계**

**최초 DOM 탐색·매핑 → 저장한 규칙으로 묶음 입력 → 입력 결과 QA**

DOM 전체를 복사하는 대신, 제목·본문·서식 도구를 역할·라벨로 찾는 규칙을 재사용하도록 설계했습니다. UI 프로필을 지원하는 환경에서는 URL·프레임·뷰포트도 기록해 같은 편집기 조건에서 규칙을 쓰도록 했습니다. 예상과 다른 화면에서는 입력을 멈추고, 입력 후에는 제목·문단 순서·누락을 확인하도록 지침을 남겼습니다.
