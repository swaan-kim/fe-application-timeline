## 목적

AI에게 요청한 내용이 실제 결과로 이어지도록, 글을 쓰기 전 목적과 확인 기준을 정하는 방법을 고민했습니다. 네이버 블로그 자동화에 적용하며 같은 지침과 화면을 반복해서 읽는 과정도 줄이고자 했습니다.

## 의도

- **요청과 검토에 같은 기준 쓰기:** 누구에게 어떤 내용을 전할지 정하고, 분량·구성·문체를 구체적으로 적었습니다. 결과를 검토할 때도 이 기준을 사용하고, 어긋난 부분은 다음 지시에 반영했습니다.
- **반복해서 읽는 정보 줄이기:** 매 단계 편집기 전체를 다시 살피는 대신, 처음 찾은 입력란과 버튼의 탐색 규칙을 재사용하도록 설계했습니다. 입력 후 제목·문단 순서·누락은 확인하고, 예상과 다른 화면에서는 멈추도록 했습니다.

## 성과

글쓰기 지침량을 약 2,200→900토큰으로 줄였습니다. 대표 원고를 작성할 때 읽는 지침만 비교한 수치이며, DOM 재사용에 따른 절감량은 아닙니다.

긴 지시를 추가하기보다 원하는 결과를 분명히 하고, QA에서 발견한 차이를 다음 요청에 반영하는 방식이 중요하다는 점을 배웠습니다.

**브라우저 제어 설계**

**최초 DOM 탐색·매핑 → 저장한 규칙으로 묶음 입력 → 필요한 항목만 QA**

제목·본문·서식 도구를 DOM 요소에 대응시키되, DOM 전체나 일시적인 요소 ID 대신 역할·라벨 기반 탐색 규칙을 재사용하는 설계입니다. 로컬 UI 프로필을 지원하는 경우 URL·프레임·화면 크기와 마지막으로 성공한 규칙을 함께 저장하도록 했습니다.
