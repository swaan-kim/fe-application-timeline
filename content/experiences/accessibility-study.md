## 목적

원하는 결과와 완료 기준을 먼저 정해, AI에게 요청한 내용과 실제 결과의 차이를 줄이고자 했습니다. 네이버 블로그 자동화에서는 같은 화면 구조를 반복해서 읽는 데 쓰이는 토큰도 줄이고자 했습니다.

## 의도

- **‘무엇을 하면 완료인가’부터:** 독자와 글의 목적에 맞춰 분량·구성·문체를 정했습니다. QA에서도 같은 기준으로 확인하고, 어긋난 부분은 다음 지시에 반영하는 방식으로 접근했습니다.
- **한 번 파악한 화면 구조 재사용:** 처음 편집기를 탐색할 때 제목·본문·서식 도구를 DOM 요소와 연결하고, 요소를 찾는 규칙을 저장해 재사용하도록 설계했습니다. 매 단계 전체 DOM을 다시 읽는 대신 필요한 정보만 쓰려는 선택입니다.
- **검증은 줄이지 않고, 반복 탐색만 줄이기:** 저장한 규칙으로 입력한 뒤 제목 일치·문단 순서·누락 여부를 확인하도록 했습니다. 화면 구조가 달라지면 입력을 멈추고 다시 확인하도록 했습니다.

## 성과

필요한 글쓰기 지침만 읽도록 정리해, 대표 원고 기준 지침량을 약 2,200→900토큰으로 줄였습니다. 이 수치는 DOM 재사용 효과가 아닌 글쓰기 지침량의 비교입니다. 학습의 초점은 지시를 길게 쓰는 것보다, 목적과 QA 기준을 맞추고 반복해서 읽는 정보를 줄이는 데 있었습니다.

**브라우저 제어 설계**

**최초 DOM 탐색·매핑 → 저장한 규칙으로 묶음 입력 → 필요한 항목만 QA**

DOM 전체나 일시적인 요소 ID 대신, 입력란·버튼의 역할과 라벨을 바탕으로 요소를 찾는 규칙을 재사용하는 설계입니다. 로컬 UI 프로필을 지원하는 브라우저에서는 URL·프레임·뷰포트와 마지막으로 성공한 탐색 규칙을 함께 저장하도록 했습니다.
