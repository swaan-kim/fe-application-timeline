## 목적

‘잘 써줘’라는 요청을 검토 가능한 기준으로 바꾸고, AI가 만든 원고와 사용자가 편집기에서 보는 결과 사이의 간극을 줄이고자 했습니다.

## 의도

- **목적을 검토 기준으로:** 누구에게 무엇을 전달할지 먼저 정하고, 독자·핵심 메시지·문체를 작성과 수정의 공통 기준으로 삼았습니다. ‘자연스럽게’ 같은 추상적 요청을 구체적인 편집 기준으로 바꾸고자 했습니다.
- **원고와 화면을 따로 검증:** 글자 수·제목 수·중복은 Python 검사로 확인하고, 브라우저에서는 제목 일치·문단 순서·서식·누락을 확인하도록 설계했습니다. 원고가 맞아도 편집기 입력 결과까지 맞는 것은 아니기 때문입니다.
- **실패 지점을 좁히는 FE 관점:** 제목·본문·서식 도구의 탐색 규칙과 URL·프레임·뷰포트 맥락을 구분했습니다. 예상한 편집기 상태와 다르면 입력을 멈추고 해당 단계부터 점검하도록 제어 지침을 구성했습니다.

## 성과

대표 원고 기준으로 글쓰기 지침을 약 2,200→900토큰으로 줄였습니다. 지침의 길이보다, 목적을 명시하고 같은 기준으로 결과를 다시 검토할 수 있게 만드는 것이 중요하다는 점을 배웠습니다. 이 수치는 지침량 비교이며, 글의 품질 향상을 측정한 값은 아닙니다.

**브라우저 제어 설계**

**Markdown 원고 → 편집기 요소 매핑·묶음 입력 → 화면 상태 검증**

Markdown을 원고의 기준으로 유지하고, 역할·라벨·안정적인 선택자를 통해 편집기 요소에 대응시킵니다. 원고와 서식을 묶어 입력한 뒤 화면 결과를 대조하도록 해, 내용 수정과 브라우저 조작을 분리했습니다.

현재는 Markdown·Python 검사와 브라우저 제어 지침으로 구성되어 있으며, 원고 파일을 직접 전달하는 Playwright MCP 엔진은 별도 연결 예정입니다.
